JS LEGALTECH CONTROL v2.0 — AUTENTICACIÓN SEGURA

CAMBIOS APLICADOS
1. Se eliminó completamente el formulario de configuración inicial del Superadministrador.
2. Una cuenta sin perfil autorizado ya no puede ingresar ni asignarse un rol.
3. El login busca perfiles de personal y clientes habilitados.
4. Los usuarios con debeCambiarPassword=true deben cambiar la contraseña antes de entrar.
5. El alta y restablecimiento de usuarios de personal ahora se realiza mediante Cloud Functions y Firebase Admin SDK.
6. Las reglas de Firestore impiden que un usuario se cree a sí mismo o modifique su propio rol.

CONFIGURACIÓN DEL PRIMER SUPERADMINISTRADOR
A) Crear manualmente la cuenta en Firebase Authentication.
B) Crear el documento personal/{UID} en Firestore con, como mínimo:
   uid: "UID_DE_AUTHENTICATION"
   nombre: "Nombre completo"
   correo: "correo@despacho.com"
   usuario: "nombre.usuario"
   rol: "Superadministrador"
   estado: "Activo"
   activo: true
   debeCambiarPassword: true

Al iniciar sesión con la contraseña temporal, el sistema solo mostrará el formulario de cambio obligatorio de contraseña.

DESPLIEGUE NECESARIO
1. Instalar Firebase CLI si aún no está instalado:
   npm install -g firebase-tools
2. Iniciar sesión:
   firebase login
3. Desde la raíz del proyecto:
   firebase use --add
4. Instalar dependencias:
   cd functions
   npm install
   cd ..
5. Publicar funciones y reglas:
   firebase deploy --only functions,firestore:rules
6. Subir el frontend a GitHub:
   git add .
   git commit -m "v2.0 - Autenticación segura y cambio obligatorio de contraseña"
   git push origin main

NOTA IMPORTANTE
GitHub Pages solo publica el frontend. Las Cloud Functions y las reglas deben publicarse con Firebase CLI.
